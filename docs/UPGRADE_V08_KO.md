# Aesthetic Manager v0.8 — 기존 Supabase 프로젝트 업그레이드

대상: v0.7/0.7.1에서 이미 `aesthetic-manager` Supabase 프로젝트와 Cloudflare Pages를 만들고, 매장 또는 로그인 계정을 등록한 사용자.

## 핵심 개념

**로그인 계정과 직원 프로필은 별개입니다.** 로그인 계정에는 최고관리자(owner), 관리자(manager), 직원(therapist) 권한이 있으며, 실제 직원 프로필에는 이름·직책(원장/실장/피부관리사 등)·접속 계정 연결 여부가 있습니다.

- 공용 방식: 최고관리자 1개 계정, 여러 직원 프로필(로그인 계정 없음). 업무 화면에서 담당자를 선택합니다. 다만 공용 로그인은 **실제 조작자를 계정 단위로 감사할 수 없습니다**.
- 개인 방식: 직원 프로필을 먼저 만든 뒤 48시간, 1회용 초대코드를 전달합니다. 직원이 별도 이메일 계정 또는 (SMS 활성화 후) 휴대폰 계정으로 로그인해 코드를 입력하면 기존 프로필에 연결됩니다.
- 혼합 방식: 모든 직원 프로필은 등록하되 일부만 개인 로그인 연결을 합니다.

직책과 권한은 다릅니다. 예를 들어 직책이 '원장'이라도 계정 권한을 '관리자'로 설정할 수 있습니다. 매장을 최초 생성한 로그인 계정만 최고관리자입니다.

## 1. 새 SQL만 실행 (기존 데이터 보존)

1. 기존 Supabase Dashboard에서 **이미 사용 중인 `aesthetic-manager` 프로젝트**를 선택합니다.
2. 이전과 동일한 Supabase 프로젝트의 **SQL Editor → New query**를 선택합니다.
3. `supabase/migrations/002_accounts_staff_phone_ready.sql` 전체를 붙여넣고 **Run**을 누릅니다.
4. **`001_ongeol_initial.sql`을 재실행하거나 기존 테이블을 삭제하지 마세요.** `002`는 기존 `shops`, `shop_members`, `shop_states`를 보존하면서 `staff_profiles`, 계정 연결 RPC 및 새 권한 규칙을 추가합니다.
5. **Table Editor → `staff_profiles`**가 생성되었는지 확인합니다. 기존 `shop_states` 고객·예약 데이터는 그대로 있어야 합니다.
6. Supabase SQL Editor에서 오류가 나면 먼저 실행을 멈추고 그 오류를 확인하세요. 성공 전까지 새 앱을 배포하지 않습니다.

> 데이터 안전: 변경 전에 `shop_states` 데이터를 백업하고 마이그레이션을 적용하세요. 무료 Supabase 프로젝트에는 자동 백업이 기본 포함되지 않을 수 있습니다. 실제 고객정보가 있다면 안전하게 저장하고 관리하세요.

## 2. Cloudflare Pages 재배포

1. 전체 프로젝트 ZIP을 압축 해제합니다.
2. Python이 설치되어 있다면 프로젝트 루트에서 `python configure_cloudflare.py` 실행.
3. 예전에 사용하던 Supabase **Project URL**, **Publishable key** 입력. (둘 다 기존 프로젝트에서 복사합니다.)
4. `Phone SMS provider configured? (y/N)`에는 **지금 SMS 업체를 연결하지 않았다면 `N` 입력**.
5. 생성된 `aesthetic_manager_pages_configured.zip`을 기존 Cloudflare Pages 프로젝트의 **새 배포**로 업로드합니다. `index.html`은 ZIP 최상위에 있습니다.
6. 강력 새로고침을 하고 로그인을 확인합니다. 동일 URL, 동일 Supabase 프로젝트이므로 기존 계정과 매장에 연결됩니다.

설정 파일의 `phoneAuthEnabled`는 **문자 서비스를 실제 설정·시험한 뒤에만** `true`로 설정하세요. 앱에 입력하는 키는 반드시 공개 Publishable key입니다. DB 비밀번호·secret·service_role 키를 웹앱에 넣으면 안 됩니다.

## 3. 기존 매장에 직원 추가하기

- 기존 관리자 이메일 계정으로 로그인 → **설정 → 직원·계정 연결 → 직원 등록**
- 직원 이름, 직책, 계정 연결 시 사용할 권한(직원 또는 관리자)을 지정합니다.
- 별도 계정이 없어도 직원 프로필은 즉시 예약 담당자로 선택할 수 있습니다.
- 계정이 필요하면 해당 직원의 **초대코드 발급**을 누릅니다. 코드를 비공개 채널로 전달합니다.
- 직원은 별도 로그인 계정을 만들고, **매장 시작하기 → 기존 매장에 직원으로 참여**에서 코드를 입력합니다.
- 48시간이 지난 코드나 이미 사용한 코드는 사용할 수 없습니다.

**기존 매장**에서는 매장 이름과 기존 최고관리자 로그인을 그대로 유지합니다. 새 최초 등록 화면은 **새로 매장을 개설하는 사람에게만** 표시됩니다.

## 4. 신규 매장 시작 화면

첫 계정 로그인 → 매장 이름 입력 → 첫 번째 직원 이름/직책 입력(선택) → 첫 직원과 관리자 로그인 계정을 연결할지 선택 → 매장 생성. 첫 번째 직원 등록은 나중에 해도 됩니다. 첫 로그인 계정의 권한은 항상 최고관리자이고, 직책을 '원장'으로 자동 지정하지 않습니다.

## 5. 직원 권한의 현재 범위

| 로그인 권한 | 가능 | 현재 제한 |
| --- | --- | --- |
| 최고관리자 (`owner`) | 직원 등록/초대, 권한 수정, 매장 이름 변경, 모든 고객/예약 편집 | 개인 직원별 감사는 계정 구분이 있어야 가능 |
| 관리자 (`manager`) | 고객·예약·회원권 등 매장 업무 편집 | 직원 계정 초대/권한 변경은 불가 |
| 직원 (`therapist`) | 매장 데이터 조회, 본인 휴대폰 추가 | 고객/예약 수정은 아직 불가 |

이 제한은 임시 설계입니다. 업무 전체가 매장별 JSONB 한 컬럼에 저장되어 고객별·업무별 RLS를 안전하게 구현할 수 없기 때문입니다. 향후 고객·예약·관리·회원권·정산 테이블을 정규화하고 업무별 서버 권한을 구현한 뒤 직원별 제한 편집을 허용할 예정입니다. 실제 고객의 민감한 자료를 투입하기 전에 운영 보안 및 동의·보관정책 검토가 필요합니다.

## 6. 휴대폰 로그인 (유료 SMS 업체 설정 전에는 비활성)

Supabase 공식 안내: <https://supabase.com/docs/guides/auth/phone-login>.

1. Supabase Dashboard → 기존 프로젝트 → **Authentication → Sign In / Providers** (UI에 따라 Auth Providers) → **Phone**.
2. **SMS 발송업체를 등록**합니다. 예를 들어 Twilio 계정을 만들고 필요한 SMS 발신 설정/자격정보를 Supabase의 Phone 설정에 입력합니다. 한국 `+82` 번호로 실제 문자가 도착하는지 먼저 시험하세요. 공급업체 요금·한국 발신 규정·시험 계정 제한을 확인하세요.
3. SMS 남용에 대비해 **CAPTCHA 및 인증번호 전송량 제한**을 설정합니다. 무료 Supabase DB ≠ 무료 SMS 인증입니다.
4. `configure_cloudflare.py`를 다시 실행하면서 `Phone SMS provider configured?` 질문에 **Y** 입력 후 Cloudflare 재배포.
5. **이미 이메일로 매장을 등록한 관리자**는 먼저 기존 이메일 계정으로 로그인해야 합니다. 앱 **설정 → 휴대폰 로그인 → 기존 계정에 휴대폰 추가**를 눌러 SMS 인증을 완료합니다. 이후 로그아웃하여 휴대폰 OTP 로그인으로 동일 매장에 들어오는지 확인합니다.
6. 아직 기존 이메일 계정과 연결하지 않은 휴대폰으로 바로 로그인하면 **별도 신규 사용자**가 만들어져 기존 매장이 보이지 않을 수 있습니다. 기존 이메일 사용자를 삭제하지 마세요. 직접 SQL로 `auth.users`를 수정하지 마세요.
7. 이메일 로그인은 안전한 복구 수단으로 계속 유지하는 편이 좋습니다. 공유 계정·공유 휴대폰은 누가 작업했는지 추적이 어렵고, SMS를 가진 사람에게 관리 권한이 노출될 수 있습니다.

**비용:** Supabase Phone OTP 자체를 사용하더라도 SMS 실제 발송 비용은 별도 업체에서 발생할 수 있습니다. 발신 국가·메시지 종류·볼륨에 따라 다르므로 금액을 고정해 기입하지 않았습니다. 저비용 대안으로 카카오 로그인 등을 추후 검토할 수 있지만 이번 프로젝트 코드에는 연결하지 않았습니다.

## 변경 내역과 테스트 범위

- 로그인: 이메일/비밀번호 유지, 옵션형 휴대폰 OTP UI 및 REST 요청, 기존 계정 휴대폰 변경 확인 경로
- DB: `staff_profiles` + 직원 생성/수정/비활성 + 계정 연결형 초대코드 RPC
- UI: 최초 매장 개설 폼, 직원 설정 화면, Aesthetic Manager와 매장 브랜드 분리
- 권한: 일반 직원의 매장 JSON 저장 거부(서버 RPC에서 강제), 사진 쓰기도 관리자 이상으로 제한
- 테스트: Node 단위 테스트 + 모의 Supabase 환경 Chromium 스모크 테스트
- **미검증:** 사용자의 실제 Supabase 프로젝트 SQL 실행, 실제 SMS 발송, 실제 Cloudflare 배포 및 기기 실사용

## 문제가 생겼을 때

- `function aesthetic_create_shop ... does not exist`: SQL `002` 적용이 완료됐는지 확인합니다.
- `relation staff_profiles does not exist`: SQL `002`를 올바른 프로젝트에서 실행했는지 확인합니다.
- `SMS provider not configured`: Email로 로그인하세요. SMS 공급업체를 먼저 설정해야 합니다.
- `already_belongs_to_shop`: 이미 다른 매장에 가입된 사용자입니다. 다른 신규 계정을 사용하거나 관리자의 도움을 받아야 합니다.
- 새 배포 후 이전 화면이 보임: Cloudflare에 업로드한 ZIP과 PWA 캐시가 최신인지 확인하고 앱을 강력 새로고침하세요.
