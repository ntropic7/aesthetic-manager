# 온결 매니저 — 개인정보 책임 구조 및 법률 검토 초안

> 기준일: 2026-10-26. 대한민국 개인정보 보호법 2026-09-11 시행본 검토. **법률 자문서가 아니다.** 사업자 정보, 실제 데이터 흐름 및 하위 수탁자 계약 검토 전 공개·상용 이용 금지. 조문 및 공식 자료 링크는 아래 참조.

## 1. 사업 모델과 법적 주체

| 정보/처리 | 처리 목적을 정하는 자(일반적인 가정) | 플랫폼의 지위 | 참고 |
| --- | --- | --- | --- |
| 매장 고객명, 연락처, 예약 및 방문 이력 | 개별 매장 | 매장으로부터 위탁받는 수탁자 | 플랫폼이 목적을 독자 결정하거나 2차 활용하면 별도 지위 검토 |
| 고객 상담 녹음, 피부/건강 상태, 전후 사진 | 개별 매장 | 수탁자 및 외부 AI/STT·클라우드 재위탁 가능 | 민감정보/동의/국외이전 검토 강화 |

| 온결 매니저 자체 광고/데이터 분석 | 별도 검토 | 운영사 독자 처리자 가능 | 위탁 계약만으로 허용되지 않음 |

### 책임 배분

- 매장은 고객정보의 적법한 수집·이용 근거 확보, 처리 목적/항목/보유기간 결정, 민감정보 별도 동의(해당 시), 위탁 사실 공개, 수탁자 감독 등의 의무를 진다.
- 운영사는 수탁자로서 목적 외 처리 금지, 보안 안전조치, 재위탁 동의 등 법적 의무를 진다. 플랫폼 보안 사고·무단 활용에 대해서는 운영사 책임이 문제 될 수 있다.
- 무동의 고객 등록의 법적 책임은 **누가 어떤 근거로 왜 처리했는지**와 법적 요건 충족 여부에 따라 결정된다. 계약 이행에 필요한 최소 예약정보는 동의 외 근거를 검토할 수 있다. 무조건 ‘동의서 없으면 위법’도, ‘위탁이므로 플랫폼은 무책임’도 잘못된 전제다.
- 개인정보 보호법 제26조제7항은 수탁자의 위법 처리로 인한 손해배상책임에 대해 수탁자를 개인정보처리자의 소속 직원으로 보며, 제8항은 수탁자에 다수의 개인정보 처리 의무를 준용한다. 계약 문구만으로 법정 책임을 배제할 수 없다.

## 2. 직원정보: 최초 직원 등록과 개별 계정

- **명단만 등록:** 이름, 직책, 근무 시간, 담당 예약처럼 근로계약/위탁계약 이행·업무 운영에 필요한 최소 정보는 적법한 다른 법적 근거(개인정보 보호법 제15조제1항제4호 등) 가능성을 개별 검토한다. 모든 직원에게 무조건 선택권 없는 동의를 요구하지 않는다.
- **고지:** 동의 없이 처리할 수 있는 항목과 근거를 처리방침 공개 또는 별도 안내 등으로 구분한다(제22조제3항). 관리자 '고지 완료' 기록은 **관리자의 진술**, 직원 본인의 직접 확인과 구분해야 한다.
- **본인 계정 연결:** 계정을 만든 실제 직원이 온결 매니저의 이용약관·계정 개인정보 처리방침을 직접 확인한다. 초대 코드 승인과 실제 인사정보 처리 근거는 별개의 사건이다.
- **직원 민감정보/생체정보/사적 내용:** 업무명단에 불필요하므로 기본 수집 금지. 별도 정당한 근거/동의 및 최소화 필요.
- **원장도 직원이 될 수 있지만 자동 생성 금지:** 관리자 계정과 직원 명부를 분리한다.
- **퇴사:** 로그인 권한 즉시 차단하고, 법적 보존 필요 기록은 접근제한·보존기간을 지키며 정리. 업무 기록 보존과 과거 담당자 이력 보존은 구분한다.

## 3. 고객정보: 목적별 처리 근거

| 정보 | 원칙적 처리 정책 | 서비스 구현 |
| --- | --- | --- |
| 이름/연락처/예약 | 계약 체결·이행에 필요한 범위 또는 실제 동의 등 적법한 근거 | 새 고객 생성 시 목적/근거 선택 및 감사기록 |
| 건강상태·알레르기·질환 관련 내용 | 민감정보에 해당하는지 판단. 해당하면 **별도 동의** 또는 법령 근거 | 고객 기본정보와 분리하고 동의 증빙 없는 저장 차단(일부 필드) |
| 상담 녹음 및 전사·AI 분석 | 대화 참여자에 대한 적정 고지·동의와 목적·보관·제3자 전송 검토 | 별도 녹음 증빙, API 연결 전 재점검 |
| 고객 전후 사진 | 개인식별 가능 사진이면 개인정보. 목적에 맞는 근거·접근제어. 홍보 공개는 별도 근거 | 비공개 스토리지, 별도 수집 증빙. 공개 동의와 내부 기록을 혼동하지 않음 |
| 광고 메시지/프로모션 | 광고성 수신동의 및 수신거부 정책 분리. 정보성 예약톡과 구별 | 수신동의 증빙 없이 캠페인 발송 금지 |
| 차량번호 | 주차 서비스 제공 필요성 판단, 불필요한 장기보관 방지 | 선택 필드 및 별도 보존 기준 검토 |

**중요:** 화면에서 매장 직원이 '동의 받음'을 선택하는 것은 실질적 동의의 증명이 아니다. signed form/e-consent 원본, 버전, 거절/철회 처리, 정보주체 요청 응대가 필요하다.

## 4. 하위 수탁자·국외이전

- **호주 Supabase → 서울**: 프로젝트 지역은 변경 불가. 서울에 새 프로젝트를 생성해 재설치(데이터가 없을 때) 또는 마이그레이션. 새 Project URL/Publishable key로 웹앱 갱신.
- 서울 리전 DB·Auth·Storage라도 공급자의 지원·운영 등에 국외 처리가 발생할 수 있다. Supabase DPA, 데이터 위치 FAQ, 하위 수탁자 목록을 확인하고 실제 흐름에 따라 국외이전 법적 근거를 판단한다.
- 개인정보 보호법 제28조의8은 계약 이행에 필요한 처리위탁·보관 등에서 요건을 충족한 처리방침 공개/고지 등의 별도 근거를 허용하므로 **국외 이전=항상 개별 동의**는 아니다.
- 향후 AI 음성/상담 전송은 공급사·국가·보관·학습 이용 여부·재위탁·동의·철회 등 추가 검토 **완료 전 연결 금지**.
- 클라우드 사업자의 DPA를 사용한다는 사실만으로 국내법 요건 충족이 자동 보장되는 것은 아니다.

## 5. 필수 계약/공개문서 및 서명 주체

1. **온결 매니저 서비스 이용약관** — 계정 사용자(원장·직원) 본인.
2. **온결 매니저 개인정보 처리방침** — 플랫폼 운영사 처리자 계정 정보용. '방침 확인'은 처리동의와 구분.
3. **매장↔플랫폼 개인정보 처리위탁 계약/부속서** — 매장 대표(권한자)와 운영사. 목적 외 처리 금지, 안전조치, 재위탁 동의, 점검·감독, 사고 대응, 파기/반환, 책임, 국제처리 경로 등을 명시.
4. **매장 자체 개인정보 처리방침·고객 안내** — 매장 명의, 위탁 업체/업무 공개, 목적·보유·연락처 등.
5. **고객별 목적·필요 법적 근거 기록** — 매장이 기록, 동의 기반이면 실제 서명 증빙 보존.
6. **개인정보 관련 민감/녹음/사진/광고 별도 문서** — 정보주체에게 각각 구분하고 선택을 강제 결합하지 않음.
7. **직원 명부 개인정보 안내** — 매장 명의로 업무상 최소 항목 처리 목적·법적 근거 안내, 직원 본인 계정의 플랫폼 방침과 분리.

## 6. 설계상 한계와 출시 차단 조건

v1.1은 **법률 검토용 문서와 부분적인 서버 차단/증빙 로그를 구현한 프로토타입**이다. 기존 v1.0의 JSONB 전체 저장 구조는 자유입력 필드가 많아 정보 유형을 완전히 분류하거나 직원별 열 권한을 실효적으로 분리할 수 없다. 고객 연락처·민감정보·직원 접근로그, 고객 삭제 요청·동의 철회 효과, 정기 백업/복구, 유출 통지, 템플릿 버전, 실제 전자서명 서비스가 검증될 때까지 상용 운영 금지.

**출시 차단 체크:** 법무 확정 문서·운영주체 등록 / 매장 계약 효력·동의 이력 / 고객 기본·민감 구분 / 테이블 정규화 RLS / 접근 감사로그 / 사진·녹음 권한 / 수탁·재위탁 목록 공개 / 보관·파기 / 고객 권리행사 / 백업복구 / 계정 보안 / 국외 이전 평가 / 취약점 테스트 / 실제 기기 통합 테스트.
