# 온결 매니저 개인정보 안전운영 단계 (승인 게이트)

- **0단계 — 개발 샌드박스 (현재 v1.1):** 가상 고객만. 개인정보 관련 문서는 초안, 운영 법적 확약 아님.
- **1단계 — 인프라:** Seoul 리전 새 Supabase 프로젝트, RLS 실DB 검증, 관리자 MFA, 비밀키 관리, Cloudflare 고정 URL, 서비스 운영자 신원 및 담당 연락처 확정.
- **2단계 — 법률 문서:** 변호사/개인정보 전문 자문 검토로 약관·운영사 처리방침·매장 처리방침 샘플·위탁계약·하위수탁자/국외이전 고지 확정. 각 문서 버전과 변경일자 관리. 초안 버전으로 받은 확인은 확정본을 대체하지 않음.
- **3단계 — 직원:** 가입 계정 직접 확인, 매장 직원명부 목적·고지, 퇴직자 접근 차단, 계정 없는 직원 관리자는 '직원 직접 동의'라고 표시하지 않음.
- **4단계 — 고객 기본 정보:** 예약 이행에 필요한 최소 항목 수집, 근거 선택/기록, 처리 목적·보유기간 안내. 동의 근거를 택했다면 원본 서명/이메일 증빙 연결. 개인정보 요청 처리 창구 운영.
- **5단계 — 민감/녹음/사진/마케팅:** 각각 별도 안내/동의/철회 흐름 구현·검증. LLM/STT 공급자와 국외 처리를 별도로 확인. 고객이 거절한 기능은 비활성화하지만 기본 예약 서비스를 자동 거절하지 않음.
- **6단계 — 보안:** 고객·예약·상담·증빙을 정규화 테이블로 분리(그전까지 일반 직원 조회 차단), 고객/매장/직원별 최소권한 RLS, 서버 감사로그, 접근 이력, 관리자 MFA, API 악용·데이터 유출·계정 해킹 테스트, 자동 백업 및 복구 리허설.
- **7단계 — 제한적 파일럿:** 개인정보 영향·위험평가, 유출대응·권리행사·파기 시나리오, 소규모 동의된 실사용자와 운영검증. 운영기록과 개선사항 남김.
- **8단계 — 상용 공개:** 문서 버전 및 동의 업데이트, 지속 점검 담당자 지정, 정기 재위탁·보안 점검, 사고 통지/신고 절차 확인.

**Release Gate:** 2~6단계 중 누락 사항이 있으면 실제 고객 이름·전화·건강기록 저장을 위한 운영 전환 금지.
