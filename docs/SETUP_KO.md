# 온결 매니저 v1.0 설치/업그레이드 안내

## 이미 Supabase + Cloudflare 연결한 경우 (권장)

1. [Supabase Dashboard](https://supabase.com/dashboard) → 기존 `aesthetic-manager` 프로젝트 선택 → **SQL Editor**.
2. `supabase/migrations/004_shop_join_approval_and_staff_integrity.sql` 파일의 **전체 SQL**을 붙여 넣고 실행합니다. (기존 001/002/003 실행 전제.)
3. 성공 후 **로그인·매장·직원 데이터는 삭제하지 않습니다.** 기존 등록 고객이 없어도 프로젝트를 초기화할 필요가 없습니다.
4. 전체 프로젝트 압축 해제 후 터미널에서 `python configure_cloudflare.py` 실행.
5. 기존 Supabase **Project URL**과 **Publishable key** 입력. `service_role` 또는 `secret`을 절대 입력하지 마세요.
6. 새로 생성된 `aesthetic_manager_pages_configured.zip`을 기존 **Cloudflare Pages** 프로젝트에서 **Create deployment / Upload assets**로 배포.
7. 브라우저 강력 새로고침(Ctrl+Shift+R), PWA 설치 사용자는 앱 새로고침/재설치. 서비스워커 캐시 버전 v100.

## 새 Supabase 프로젝트의 경우

`supabase/INSTALL_NEW_PROJECT.sql` 한 파일을 SQL Editor에서 실행합니다. 그 외 설치 순서는 위와 같습니다.

## 실제 확인 시나리오

### 신규 매장 관리자

1. 이메일로 회원가입하고 확인 메일 인증 → 로그인.
2. **신규 매장 개설** 선택.
3. 매장명과 **첫 직원 이름** 필수 입력. 첫 직책은 비워도 되며, 관리자 계정과 직원 연결 여부는 선택.
4. `설정 → ① 매장 정보 관리`에서 관리실·좌석 등을 설정.
5. `설정 → ② 직원·직책 관리`에서 직원·직책을 편집.
6. `설정 → ④ 계정·매장 연결 승인`의 연결 코드를 필요한 직원에게 전달.

### 기존 매장 직원

1. 별도 이메일로 가입 후 로그인 → **기존 매장 연결 요청** 선택.
2. 전달받은 **매장 연결 코드** 입력 → 승인 대기. 승인 전 고객·매출은 보이지 않아야 합니다.
3. 관리자가 새 요청을 확인하고 **기존 직원 연결** 또는 **새 직원 등록 후 연결**로 승인.
4. 신청 계정에서 **승인 상태 다시 확인**을 누르면 매장에 진입합니다.
5. 관리자/일반 직원의 권한은 직책과 별도입니다. 일반 직원은 파일럿 현재 조회 전용입니다.

### 직원 삭제/담당 이관

1. `설정 → ② 직원·직책 관리`에서 직원 삭제.
2. 최소 1명만 남았다면 **최소 1명 필수** 안내가 나오고 삭제할 수 없습니다.
3. 예약·서비스·정산 등에 연결돼 있으면 항목별 건수를 표시합니다.
4. 다른 직원 선택 → **담당 기록 이관** → 이관 완료 후 최종 삭제.
5. 로그인 계정 연결이 있으면 관리자/직원 계정 연결을 먼저 해제합니다.
6. 직원이름으로 묶인 과거 기록이 통째로 이동하므로 이관 대상을 반드시 확인하세요.

### 타임테이블 확대/축소

- 노트북/PC: 표시 프레임 높이는 약 518px로 고정. `−`를 누르면 09:00~21:00 전부 프레임 안에 들어오도록 축소.
- `+`는 시간/예약 카드의 내부 스케일만 크게 하며 프레임은 그대로. 확대되어 넘치는 부분은 프레임 내부를 스크롤.
- 한 관리사 주간 7일 보기의 열 수는 확대/축소와 무관함. 별도의 `주간 한눈에` 버튼이 너비 표시를 변경합니다.

## 중요 제한

Supabase/PostgreSQL RPC·RLS 정책은 앱을 연결한 **네 실제 프로젝트에서 추가 검증**이 필요합니다. 테스트 코드는 모의 서버 기반입니다. 실고객 정보를 넣기 전에 백업·삭제·권한 점검을 완료하세요. 현재 구조는 예약/회원권 정규화 전 파일럿입니다.
