## 2. 문제 정의

소규모 예약 기반 매장(1~5인)은 관리자의 설정시간이 적고 직원별 별도 로그인보다 하나의 관리자 계정으로 시작하기 쉬움. 하지만 고객 상담·예약·결제·재방문 관리가 종이·메신저·엑셀에 나뉘어 반복 입력되는 불편함이 발생할 수 있음. 이는 제품 가설이며 출시 전 매장 인터뷰로 검증해야 함.

## 3. 차별점 — 검증할 제품 가설

### P1. 상담 → 승인 → 다음 행동을 한 번에
- 상담 녹음/텍스트에서 **고객 프로필 변경 제안, 후속업무, 다음 예약 제안**을 생성
- 변경 전/후 값과 인용 근거를 함께 보여주고 **사람이 선택 승인**
- 직원이 매번 세 메뉴에 입력하지 않아도 고객카드·후속업무가 이어짐
- 성공 지표: 상담 종료부터 후속처리까지 소요시간, AI 수정률, 재예약 전환율
- 현재 상태: **규칙 기반 제안/선택 승인 시연**, 실 LLM/STT 미연결

### P1. 한 화면에서 고객을 기억하는 '다음 방문 카드'
- 다음 예약 전에 지난 요청, 선호, 주의사항, 진행권/결제 상태, 최근 관리 요약을 자동 노출
- 필수 정보만 먼저, 상세 이력은 펼침
- 성공 지표: 고객 응대 준비시간, 기록 누락률
- 현재 상태: **고객 360°와 상담·회원권 데이터 연결 있음**; 방문 전 브리핑 카드 특화는 향후 구현

### P1. 1~5인 매장의 설정·가입 단순화
- 신규 매장 최소 1명 필수, 직책은 자유입력, 계정은 별도 연결/승인
- 설정은 매장/직원/서비스/계정/개인정보/고급 기능의 6개 탭
- 성공 지표: 처음 1건 예약 생성까지 클릭수/분, 초기 설정 이탈률
- 현재 상태: **v1.3 설정 UX 반영**

### P2. 예약 직후/방문 후 실행 제안
- 노쇼 관리, 잔여 회원권, 고객별 적정 재방문일을 한 화면에서 알림
- 메시지는 안내/광고를 분리하고 승인 후 발송
- 성공 지표: 30·60일 재방문율, 사용권 소진 후 재구매율
- 현재 상태: 회원권·노쇼·메시지 초안 제공, 발송/예측 자동화 미연결

### P2. 외부 노출 + 내부 실제 전환 연결
- 네이버/카카오/Google에서 관찰 가능한 지표(검색 노출/리뷰/콘텐츠)와 매장의 문의·예약·결제 이벤트를 연결
- 플랫폼별 제공 지표와 제약이 상이하므로 확인할 수 없는 순위를 만들어내지 않음
- '검색 노출 하락 → 콘텐츠 제안 → 캠페인 실행 → 예약/매출 연결'을 근거와 함께 보여줌
- 현재 상태: 수동 관측/캠페인 시뮬레이션, 외부 자동 수집 미연결

### P0. 개인정보 보호를 제품 경험으로
- 고객정보 처리의 목적·법적 근거·동의·증빙을 구분해 기록
- 직원별 계정권한과 실제 담당자를 분리
- 실제 법적/기술적 검증 없이 '인증·보안 완비' 주장 금지
- 현재 상태: 개인정보 안내/기록 기반, 개별 업무 DB 권한·접근 감사로그 미완료

## 4. v1.3 실제 적용한 UI 변경

- 길게 쌓였던 7개 설정 패널 → **카테고리 네비게이션 + 선택 항목 1개만 표시**
- PC: 좌측 설정 메뉴 / 우측 상세. 모바일: 가로 스크롤 가능한 설정 메뉴 / 상세
- 직책 마스터 등록·관리 페이지 제거. 직원 입력 폼에 **자유입력(선택)** 배치
- 기존 Supabase `staff_positions`는 내부 참조용으로 유지. DB 마이그레이션 불필요
- 직원 수정/삭제 및 계정 연결·승인, 프로그램, 개인정보/약관, 데이터 백업 기능 경로 유지
- 고급 기능은 기본 접힘 상태로 일상 운영자의 주의 분산 감소

## 5. 다음 UX 실험 (기능 구현 전)

1. 실제 원장 3~5명을 대상으로 **매장 생성→직원 추가→서비스 등록→첫 예약**까지 관찰하고, 메뉴 위치/명칭 이해도 기록
2. 고객 상세에서 **오늘 관리 전 준비 카드** 시제품 A/B 비교
3. 기존 메모→고객정보 업데이트·다음 예약까지 기존 업무 대비 클릭수 측정
4. 카카오/네이버 등 외부 연결은 공급자 권한·비용과 개인정보 영향을 별도 검증

### 주의

v1.3은 UI 중심 업데이트. 실제 AI·SMS·외부 채널 데이터·개인정보 상용 보안 문제를 새로 해결했다고 주장하지 않는다.
