# 온결 매니저 v1.1 개인정보 준비 + 서울 Supabase 구축

## 먼저 확인

- **운영 전 개인정보 안전 준비판**이다. 법률 문서는 초안이며, 데이터 스키마는 아직 매장별 JSONB이다. 실제 고객정보/민감정보 투입 금지.
- 기존의 v1.0 기능·API 구조는 유지하면서 계정 안내·동의 근거 기록·서버 검증 및 민감정보 관련 부분 차단을 추가했다.
- v1.1에서는 JSONB 통째 조회 노출을 막기 위해 **일반 직원(therapist) 계정의 매장 데이터 조회를 임시 차단**했다. 직원은 가입·승인과 직원정보 안내 직접 확인이 가능하다. 관리자/매니저 업무 흐름 시연 가능.

## Sydney 프로젝트에 아직 실정보가 없다면 (권장)

1. Supabase Dashboard에서 기존 프로젝트 실제 Region이 Sydney인지 확인하고, **새 프로젝트를 Seoul `ap-northeast-2`** 에 만든다. Region은 기존 프로젝트에서 직접 바꿀 수 없다.
2. 새 Supabase SQL Editor에서 `supabase/INSTALL_NEW_PROJECT.sql` 파일을 실행한다. **001~005 통합** SQL이므로 새 프로젝트에서는 개별 migration을 다시 실행하지 않는다.
3. 이메일 Auth, Production URL과 Redirect URL 설정을 진행한다.
4. 새 Project URL과 `sb_publishable_...` Publishable key를 사용한다. 관리자 비밀키/DB 비밀번호를 프런트엔드에 넣지 않는다.
5. Cloudflare Pages가 **Git 자동 배포**라면 저장소의 `web/config.js`에서 URL과 Publishable key를 새 서울 프로젝트 값으로 바꿔 push한다. `Build output directory`가 실제 `web` 폴더를 가리키는지 확인한다. GitHub 환경변수/빌드 시 치환 구조를 이미 운영 중이면 해당 변수만 변경한다. 기존 Pages 프로젝트는 그대로 유지하므로 고정 Production URL은 변경되지 않는다.
6. **Cloudflare 수동 업로드** 방식이라면 프로젝트 루트에서 `python configure_cloudflare.py` 실행 → 새 URL/공개키 입력 → 생성된 ZIP 업로드. 이제 `legal/*.html`도 포함된다.
7. 새 주소에서 이메일 재가입 후 플랫폼 이용약관/처리방침 초안 확인 → 신규 매장/기존 매장 선택 → 첫 직원 등록 → 설정 `⑦ 개인정보·처리위탁 관리` 초안 확인 → **가상 테스트 고객** 등록 및 예약/사진/동의 흐름 점검.
8. 새 프로젝트로 연결되었음을 확인한 뒤, 필요 없어진 호주 프로젝트만 정리한다. 새 프로젝트는 이전 로그인 계정이나 기존 비밀번호를 자동 이전하지 않는다.

## 기존 서울 프로젝트가 001~004까지 반영돼 있다면

`supabase/migrations/005_privacy_foundation.sql` **하나만 추가** 실행하고 프런트엔드 v1.1을 배포한다. SQL이 성공하기 전에 v1.1 화면을 배포하면 가입·고객 등록·개인정보 확인이 실패할 수 있다.

## 동의 관련 화면 테스트 (가상정보만)

- 관리자 로그인: 이용약관 **동의**와 플랫폼 개인정보 방침 **확인**을 별도로 기록한다.
- 매장 설정: 고객정보 위탁 처리 및 매장 책임 문서 **초안 확인 이력**을 남긴다. **정식 법률계약으로 보지 않는다.**
- 고객 등록: 계약 이행에 필요한 최소 정보 / 별도 동의 중 법적 근거를 선택, 동의 기반이면 서명 문서 번호를 기록한다. 서버에서 고객 근거 이벤트 없으면 저장을 거부한다.
- 고객 민감정보/녹음/사진/광고: 용도별 분리된 확인 및 서명 증빙 위치를 기록한다. 서버가 일부 명시적 필드와 사진 업로드 접근을 제한한다. JSONB 자유 텍스트 전체를 안전하게 검사하는 기능은 없음.
- 직원 등록: 최소명부 처리와 안내 필요성을 구분하며 관리자가 고지했다는 진술은 **직원 동의가 아님**.
- 직원 본인 계정: 일반 업무정보 조회는 임시 차단. 대신 직원 본인 안내 확인 이력을 저장 가능.

## 법률·보안 승인 게이트

`docs/privacy/LEGAL_REVIEW_KO.md`, `docs/privacy/CONSENT_MATRIX_KO.md`, `docs/privacy/GO_LIVE_CHECKLIST_KO.md` 파일을 확인한다. 법적 문서 확정, 사업자/대표 권한 검증, 개인정보 정규화·RLS, 동의 철회 및 삭제·백업, 사고 대응·국외 처리 경로 검토 전에는 상용 운영하지 않는다.
