# 온결 매니저 v1.2.1 — 예약 기반 매장 통합관리

Cloudflare Pages에서 배포하는 PC·태블릿·스마트폰 공용 웹앱(PWA)과 Supabase PostgreSQL/Auth/Storage 프로젝트입니다. 개발 프로젝트명은 `aesthetic-manager`, 앱 표시명은 **온결 매니저**, 로그인 후에는 매장 브랜드가 메인에 표시됩니다.

## v1.2.1 권한 표시 수정

- 직원 프로필의 `access_role`은 **계정 연결 전 기본 권한**이며, 실제 로그인 권한은 `shop_members.role`을 기준으로 표시합니다.
- 최고관리자 계정과 연결된 직원은 `최고관리자`로 표시되며 직원 수정에서 변경할 수 없습니다.
- 기존 SQL 및 고객·예약 데이터는 변경하지 않습니다. 새 SQL 실행 불필요.

## v1.1 주요 변경

1. **설정 순서:** 매장 정보(매장명·관리실/공간/좌석·주차 정책) → 직원·직책(한 페이지) → 프로그램 → 계정/매장 연결 승인 → 백업 → 외부연동.
2. **예약 시간표:** 표시 영역은 고정(PC 518px / 모바일 448px), `+/-`는 그 안에서 시간축만 확대·축소. 최소 축소=09:00~21:00 전체 표시. 직원별 열/주간 7일은 줌과 별개.
3. **신규 이메일 가입:** 첫 로그인 후 `신규 매장 개설` 또는 `기존 매장 연결 요청` 선택. 신규 매장 생성 시 직원 이름 1명 필수; 직책은 선택.
4. **기존 매장 가입:** 관리자에게 `설정 → ④ 계정·매장 연결 승인`에서 매장 연결 코드를 받아 신청 → 승인 대기 → 관리자 기존 직원에 연결 또는 신규 직원 생성 후 승인. 이전 초대코드 즉시가입 RPC는 차단.
5. **직원 삭제 보호:** 1→0명 삭제·비활성 차단, 연결 계정 분리 필수, 예약/서비스/대기예약/휴무/정산 등 연결 기록 표시 → 다른 직원으로 담당자 이관 → 삭제. 원본 데이터 변경은 Supabase RPC 트랜잭션 처리.
6. **권한 강화:** 직원(therapist) 계정은 서버 RPC에서도 JSONB 전체 저장을 금지.

## 배포/설치

[단계별 한국어 설치 가이드](docs/SETUP_KO.md)

- 기존 Supabase 프로젝트에서 `001`, `002`, `003`을 이미 실행했다면 **`supabase/migrations/004_shop_join_approval_and_staff_integrity.sql`만 추가 실행**합니다.
- 처음 만드는 Supabase 프로젝트라면 `supabase/INSTALL_NEW_PROJECT.sql`을 한 번 실행합니다(001→004 통합).
- Cloudflare Pages: `python configure_cloudflare.py` 실행 → Supabase Project URL과 Publishable key를 입력 → 생성된 `aesthetic_manager_pages_configured.zip`을 기존 Pages 프로젝트에 업로드.
- 기존 매장 데이터는 자동 삭제하지 않습니다. 과거 v0.9에서 직원이 0명인 매장은 먼저 직원 1명을 등록해 주세요.

**순서 중요: Supabase SQL 실행 → Pages 새 버전 배포.** SQL 실행 전에 새 웹앱만 먼저 올리면 RPC가 없어 작동하지 않습니다. 이전 가입 코드는 v1.1 승인 흐름에서 사용할 수 없습니다. 신규 매장 연결 코드를 발급하세요.

## 테스트

```bash
npm test
node --check web/app.js
node --check web/sync.js
python tests/smoke_browser.py  # Playwright + Chromium 필요
```

자동테스트는 **모의 Supabase**를 사용하므로 PostgreSQL SQL/RLS 마이그레이션의 실서버 실행 및 관리자 승인·이관 동시성 테스트는 실제 프로젝트에서 추가 검증해야 합니다.

## 운영 전 주의

현재 업무데이터는 매장별 JSONB 단일 객체입니다. 직원별 업무 수정 권한은 세부 테이블로 정규화하기 전까지 제한적으로 제공하며 일반 직원은 조회 전용입니다. 실제 개인정보·상담녹음·고객사진으로 운영하기 전에 개인정보 보관·삭제·권한·백업·RLS·동시편집·접근로그를 점검해야 합니다. 외부 LLM/STT·카카오톡·PG 실연동은 포함하지 않습니다.

브라우저에 `service_role` / `secret` 키를 넣지 마세요. **Publishable key**만 사용해야 합니다.

## 개인정보 관리 v1.1

* `supabase/migrations/005_privacy_foundation.sql` 추가. 기존 001~004 이후 적용. 신규 서울 프로젝트는 `supabase/INSTALL_NEW_PROJECT.sql` 사용.
* 관리자/직원 계정에 플랫폼 약관 동의·방침 확인 로그, 매장 위탁계약 초안 확인 이벤트, 고객정보 처리 근거 및 고객 민감정보·사진·녹음·마케팅 이벤트 로그를 추가.
* 직원 명부 처리의 관리자 고지 진술은 직원 본인의 직접 확인과 엄격히 구분.
* **실고객 데이터 운영 금지**: 문서 초안, JSONB 단일 매장 저장·미완성 접근감사/삭제/백업/전자동의 기능. `docs/privacy/` 운영 단계와 법률 검토사항을 참조.

**변경된 직원 계정 제한:** JSONB 단일 매장 데이터에서 일반 직원에게 고객정보가 전부 노출되는 문제를 막기 위해 v1.1 개인정보 파일럿에서는 일반 직원의 매장 데이터 조회를 임시 차단했다. 정규화/테이블별 RLS 전까지 직원 계정은 본격 이용 불가.
